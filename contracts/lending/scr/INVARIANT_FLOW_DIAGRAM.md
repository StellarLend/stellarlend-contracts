# Reserve Invariant Checking - Flow Diagrams

## Basic Operation Flow

```
┌─────────────────────────────────────────────────────────────┐
│                    deposit(user, 1000, USDC)                │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: CHECK INVARIANT BEFORE                             │

│  actual   = token_client.balance(&contract) = 5000          │
│  expected = TotalDeposits(5000) + Treasury(0) = 5000        │
│  drift    = 0                                               │
│  ✓ PASS                                                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: TRANSFER TOKENS                                    │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  token_client.transfer(&user, &contract, &1000)             │
│  → Contract balance: 5000 → 6000                            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: UPDATE ACCOUNTING                                  │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  TotalDeposits(USDC): 5000 → 6000                           │
│  UserBalance(user, USDC): 500 → 1500                        │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4: CHECK INVARIANT AFTER                              │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  actual   = token_client.balance(&contract) = 6000          │
│  expected = TotalDeposits(6000) + Treasury(0) = 6000        │
│  drift    = 0                                               │
│  ✓ PASS                                                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
                    ✓ SUCCESS - Return
```

│              withdraw(user, 500, USDC) - WITH BUG           │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: CHECK INVARIANT BEFORE                             │

│  expected = 6000                                            │
│  drift    = 0                                               │
│  ✓ PASS                                                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: UPDATE ACCOUNTING (BUGGY - wrong amount!)          │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  TotalDeposits(USDC): 6000 → 5400  (subtracted 600 not 500)│
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: TRANSFER TOKENS                                    │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  token_client.transfer(&contract, &user, &500)              │
│  → Contract balance: 6000 → 5500                            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4: CHECK INVARIANT AFTER                              │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  actual   = token_client.balance(&contract) = 5500          │
│  expected = TotalDeposits(5400) + Treasury(0) = 5400        │
│  drift    = +100                                            │
│  ✗ FAIL                                                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  🚨 PANIC AND REVERT TRANSACTION                            │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  RESERVE INVARIANT VIOLATION [AFTER]:                       │
│    asset=USDC,                                              │
│    actual_balance=5500,                                     │
│    expected_balance=5400,                                   │
│    drift=+100                                               │
│                                                             │
│  → All state changes reverted                               │
│  → Contract remains at original state                       │
│  → Bug prevented from causing damage                        │
└─────────────────────────────────────────────────────────────┘
```

## Flash Loan Flow (with Callback Exemption)

```
┌─────────────────────────────────────────────────────────────┐
│              flash_loan(receiver, USDC, 5000)               │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1: CHECK INVARIANT BEFORE                             │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  actual   = 10000                                           │
│  expected = 10000                                           │
│  ✓ PASS                                                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: SET FLASH LOAN GUARD                               │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  storage.set(FlashActive, true)                             │
│  → Invariant checks now SKIPPED                             │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: TRANSFER LOAN TO RECEIVER                          │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  token(USDC).transfer(contract → receiver, 5000)            │
│  Balance: 10000 → 5000                                      │
│  ⚠️ INVARIANT TEMPORARILY VIOLATED (but checks skipped)     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4: CALLBACK TO RECEIVER                               │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  receiver.on_flash_loan(USDC, 5000)                         │
│  → Receiver does arbitrary operations                       │
│  → If receiver calls deposit/withdraw, checks SKIPPED       │
│  → FlashActive guard prevents nested operations             │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 5: RECEIVE REPAYMENT + FEE                            │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  token(USDC).transfer(receiver → contract, 5050)            │
│  Balance: 5000 → 10050                                      │
│  Treasury(USDC): 0 → 50                                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 6: CLEAR FLASH LOAN GUARD                             │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  storage.remove(FlashActive)                                │
│  → Invariant checks now ACTIVE again                        │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 7: CHECK INVARIANT AFTER                              │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  │
│  actual   = 10050                                           │
│  expected = TotalDeposits(10000) + Treasury(50) = 10050     │
│  ✓ PASS - Invariant restored                               │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
                    ✓ SUCCESS - Flash loan complete
```

                            │

                            │
                            ▼

│  Component 3: BAD DEBT (Unrecoverable Losses)               │

                            │

```

## Decision Tree: Do I Need Invariant Checks?

```
                    START: New Function
                            │
                            ▼
              ┌─────────────────────────┐
              │  Does it transfer       │
              │  tokens in/out of       │ YES
              │  contract?              ├──────┐
              └─────────────────────────┘      │
                            │ NO               │
                            ▼                  │
              ┌─────────────────────────┐      │
              │  Does it update         │      │
              │  TotalDeposits,         │ YES  │
              │  Treasury, or BadDebt?  ├──────┤
              └─────────────────────────┘      │
                            │ NO               │
                            ▼                  ▼
              ┌─────────────────────────┐  ┌──────────────────┐
              │  Is it a pure view/     │  │  ADD INVARIANT   │
              │  query function?        │  │  CHECKS          │
              └─────────────────────────┘  │                  │
                      │ YES    │ NO        │  • Before op     │
                      ▼        ▼            │  • After op      │
          ┌─────────────┐  ┌────────────┐  │                  │
          │ NO CHECKS   │  │ CHECK IF   │  │  Multi-asset?    │
          │ NEEDED      │  │ IT CALLS   │  │  → Check both    │
          └─────────────┘  │ STATE-     │  └──────────────────┘
                           │ CHANGING   │
                           │ FUNCTIONS  │
                           └────────────┘
                                  │
                          Those functions
                          should have checks
```

## State Consistency Guarantee

```
BEFORE ANY OPERATION:
┌──────────────────┐      ┌──────────────────┐
│ Actual Balance   │  ==  │ Expected Balance │
│   (tokens)       │      │  (accounting)    │
└──────────────────┘      └──────────────────┘

DURING OPERATION:
┌──────────────────┐      ┌──────────────────┐
│ Actual Balance   │      │ Expected Balance │
│   (changes)      │  ==  │  (changes)       │
└──────────────────┘      └──────────────────┘

AFTER OPERATION:
┌──────────────────┐      ┌──────────────────┐
│ Actual Balance   │  ==  │ Expected Balance │
│   (new total)    │      │  (new total)     │
└──────────────────┘      └──────────────────┘

IF NOT EQUAL AT ANY CHECK:
┌──────────────────────────────────────┐
│  🚨 PANIC                            │
│  → Transaction reverts               │
│  → State returns to BEFORE operation │
│  → No corruption possible            │
└──────────────────────────────────────┘
```
